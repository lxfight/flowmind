# 版本变化

FlowMind 当前版本为 `v0.4.0`。这一版本让任务关系、里程碑全景和外部自动化形成连续的交付信号链。

## v0.4.0

发布时间：2026 年 7 月 31 日

### 任务编号与跨任务引用

- 任务卡片和详情稳定展示任务 ID，讨论、搜索和外部通知都能准确定位同一任务。
- 在任务描述或评论中输入 `#` 可按编号或标题引用同项目任务，并直接打开目标详情。
- 引用关系双向展示，修改或删除原文时自动同步，所有查询继续遵守项目权限边界。

### 完整里程碑时间线

- 时间线不再按“不需要、推进中、已归档”等视图分类截断，而是在同一时间轴展示全部里程碑。
- 历史与未来节点继续使用游标分页和按需加载，长周期项目仍保持稳定布局。
- 状态、风险、完成进度与关联任务在同一交付视图中连续呈现。

### 项目级外部通知

- 新增通用出站 Webhook，可订阅任务、评论和里程碑共 10 类领域事件。
- 业务事务同时写入 PostgreSQL Transactional Outbox，独立 `notifier` Worker 异步投递，不阻塞用户操作。
- 请求使用 HMAC-SHA256 签名；签名密钥加密保存、仅创建或轮换时显示。
- 公网地址强制 HTTPS，并在配置与投递阶段执行 DNS 和私网地址检查；可信内网地址仅超级管理员可开启。
- 支持数据库租约、指数退避、`Retry-After`、人工重试、投递历史和连续失败自动暂停。

### 发布与更新可靠性

- 在线更新器会根据目标版本 Compose 动态识别应用服务，升级时拉起并等待 `notifier` 健康。
- 回滚到不包含 `notifier` 的旧版本时会恢复旧服务集合，避免残留新版本 Worker。
- 文档站新增完整的签名验证、平台适配、重试策略和内网部署说明。

### 兼容性说明

- 数据库会自动执行任务引用与外部集成迁移，最终迁移版本为 `e8f0a2b4c6d8`。
- 升级后会新增 `notifier` 容器。现有任务、评论和里程碑不会补发历史 Webhook，只投递升级后发生的事件。
- 生产环境应在升级前设置稳定、随机的 `INTEGRATION_ENCRYPTION_KEY`；修改该值后已有 Webhook 密钥需要重新生成。
- 建议设置 `PUBLIC_APP_URL`，否则 Webhook 事件中的任务和里程碑地址为相对路径。
- 数据库迁移不会自动降级。回退镜像前应保留 updater 创建的 PostgreSQL 备份。

### 升级到 v0.4.0

在仓库根目录执行：

```bash
scripts/update.sh 0.4.0
```

也可以由超级管理员在“系统更新”页阅读 Release 说明并启动更新。更新完成后应确认 `backend`、`frontend`、`notifier`、`postgres` 和 `updater` 均为健康状态。

## v0.3.0

发布时间：2026 年 7 月 28 日

### 里程碑交付工作区

- 一个项目可维护多个里程碑，任务只能归属于一个里程碑，避免交付范围重复计算。
- 里程碑沿柔和曲线按自然日间隔成比例排布，明确显示当前时间、下一个节点距离和后续计划。
- 进入时间线时从当前时间开始，旧节点通过游标分页按需载入，避免长周期项目一次加载全部历史数据。
- 里程碑支持负责人、状态、目标日期、关联任务和归档视图，并接入看板筛选与任务详情。
- LLM 助手可以查询、创建和更新里程碑；写操作使用幂等键，避免重试产生重复节点。

### 报告与项目共享

- 报告历史和生成状态提升为项目级数据，同一项目的成员看到一致的报告与进度。
- 报告生成状态可以跨页面恢复，并在其他成员完成生成后自动获取最新结果。
- 报告上下文加入里程碑状态、目标日期、完成率和关联任务，阶段总结与交付计划保持一致。

### LLM 身份与执行记录

- 助手上下文注入当前用户 ID、用户名、昵称、权限与项目角色，工具调用遵守真实用户身份。
- 模型实际返回的思考内容会持久化，历史会话可恢复；没有思考内容时不会伪造。
- 思考内容与工具调用使用独立折叠区，多次工具调用逐条编号并可分别展开。
- 调用参数与执行结果分区展示，JSON 结果按字段渲染，长文本保留换行并安全折行。

### 初始化安全

- 全新部署可通过 `FLOWMIND_ADMIN_USERNAME` 自定义初始管理员用户名；账号创建后用户名仍不可修改。
- 管理员用户名必须为 3–64 位字母、数字、下划线、点或连字符。
- 空管理员密码会替换为随机密码；显式配置的密码要求 8–128 位且不再写入启动日志。

### 兼容性说明

- 数据库迁移会自动创建里程碑及共享报告所需结构，已有任务与报告无需手工迁移。
- `FLOWMIND_ADMIN_USERNAME` 只对空数据库首次初始化生效，不会重命名现有管理员。
- 旧的 LLM 历史消息可以继续读取；只有升级后产生且模型实际返回的思考内容会被记录。
- 里程碑任务互斥规则由服务端强制执行，重复分配会转移归属而不会复制任务。

### 升级到 v0.3.0

在仓库根目录执行：

```bash
scripts/update.sh 0.3.0
```

也可以由超级管理员在「系统更新」页阅读 Release 说明并启动更新。更新前应确认数据库备份空间充足，并保留随机的 `FLOWMIND_UPDATER_TOKEN`。

## v0.2.2

发布时间：2026 年 7 月

### 工作区与视觉系统

- 统一应用页面、项目对话框、任务对话框、知识库与助手面板的视觉语言。
- 引入沉浸式确认对话框，对删除、更新与回滚等高风险操作提供一致的确认路径。
- 重构知识库、通知、项目成员、报告、个人资料与系统管理页面的信息层级。
- 项目颜色选择器与创建、编辑流程使用同一套交互规则。

### 通知与活动信号

- 任务通知现在携带项目、看板与任务目标信息，可直接打开对应任务详情。
- 为旧通知回填深链数据，并在目标不存在或不可访问时提供安全降级。
- 通知页升级为可连续浏览的信号流，未读状态与时间信息更加清晰。
- 项目活动改为横向时间线，默认定位到最新事件，并使用虚拟渲染保持长列表流畅。

### 报告与知识工作区

- 报告生成加入总超时、有限重试与指数退避，覆盖网络错误、限流、服务端错误和不完整输出。
- 报告生成状态按项目隔离，切换页面后仍能恢复当前生成进度，不会串用其他项目的快照。
- 修复报告 Markdown 渲染，并限制内存中的生成快照数量。
- 优化知识文档创建、编辑、查询和助手调用流程。

### 更新与部署

- updater 在切换代码前建立恢复检查点；容器或宿主机中断后，重启可尝试恢复上一版本。
- 数据库备份前按数据库体量验证空间，备份后默认至少保留 1 GiB 可用空间。
- 更新请求支持幂等重放与状态协调，避免请求已启动但业务端误判为失败。
- 部署完成后同时检查前端、后端健康状态与后端实际版本。
- `scripts/deploy.sh` 可自动探测 PyPI、npm、Debian 与 Alpine 镜像源，并复用 BuildKit 依赖缓存。

### 兼容性说明

- 数据库迁移会自动执行，但不会自动降级；更新失败时数据库备份会保留。
- 旧通知的深链字段由迁移脚本自动回填，不需要手工处理。
- 新增的报告可靠性参数均有默认值，旧部署无需立即配置。

### 升级到 v0.2.2

在仓库根目录执行：

```bash
scripts/update.sh 0.2.2
```

也可以由超级管理员在「系统更新」页阅读 Release 说明并启动更新。生产环境应先确认 `.env` 已设置随机的 `FLOWMIND_UPDATER_TOKEN`，并为 `updater_state` 数据卷预留足够的数据库备份空间。

完整更新流程、失败恢复与镜像源选项见[部署指南](/guide/deployment#版本更新)。
